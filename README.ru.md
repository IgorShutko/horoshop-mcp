# Хорошоп MCP: неофициальный MCP-сервер для магазинов на Хорошопе

[Українська](README.md) · **Русский** · [English](README.en.md)

**Хорошоп MCP** (`horoshop-mcp`): бесплатный [MCP](https://modelcontextprotocol.io/)-сервер с открытым исходным кодом, который подключает ИИ-агентов Claude, Cursor, Codex, Hermes Agent и других к интернет-магазину на платформе [Хорошоп](https://horoshop.ua/). Сервер работает на вашем компьютере, обслуживает несколько магазинов одновременно и даёт агенту 118 инструментов для каталога, заказов, SEO, редиректов, фидов маркетплейсов, дизайна и настроек магазина.

> **Неофициальный проект.** Хорошоп MCP не является продуктом компании Хорошоп, не связан с ней и ею не поддерживается. Инструменты админки работают через внутренние недокументированные запросы, которые Хорошоп может изменить без предупреждения. Новые сценарии сначала проверяйте на тестовом магазине и только потом запускайте на рабочем.

- **118 инструментов** на трёх уровнях: публичный API Хорошопа, админка и корзина витрины.
- **Много магазинов, один сервер.** Каждый инструмент принимает аргумент `store`, поэтому агентство может работать с магазинами всех клиентов через одно подключение.
- **Безопасно по умолчанию.** 57 из 71 инструмента записи только показывают план изменений, пока вы не передадите `dryRun:false`; рискованные массовые операции требуют явного подтверждения; каждая запись проверяется повторным чтением результата.
- **Локально.** Сервер работает на вашем компьютере через stdio. Доступы лежат в файле, который контролируете вы.

## Быстрый старт

**1. Что нужно.** Node.js 18 или новее и Git.

**2. Доступы.** Создайте в админке магазина отдельного администратора (раздел **Настройки → Админы**, кнопка **Добавить**) и сохраните его логин и пароль. Та же пара работает и для API, и для инструментов админки. Подробнее: [как получить доступы Хорошопа](docs/INSTALL.ru.md#1-получите-доступы-хорошопа).

**3. stores.json.** Сохраните файл там, куда нет доступа посторонним:

```json
{
  "myshop": { "baseUrl": "https://myshop.com.ua", "login": "api-user", "password": "REPLACE_ME" }
}
```

**4. Подключите ИИ-клиент.** Клонировать репозиторий не нужно: клиент сам запускает сервер через `npx`.

Claude Code:

```bash
claude mcp add horoshop -s user -e HOROSHOP_STORES_FILE=/abs/path/to/stores.json -- npx -y github:IgorShutko/horoshop-mcp
```

Codex:

```bash
codex mcp add horoshop --env HOROSHOP_STORES_FILE=/abs/path/to/stores.json -- npx -y github:IgorShutko/horoshop-mcp
```

Cursor (`~/.cursor/mcp.json`), Claude Desktop (`claude_desktop_config.json`), Windsurf, LM Studio, Kiro и большинство других клиентов:

```json
{
  "mcpServers": {
    "horoshop": {
      "command": "npx",
      "args": ["-y", "github:IgorShutko/horoshop-mcp"],
      "env": { "HOROSHOP_STORES_FILE": "/abs/path/to/stores.json" }
    }
  }
}
```

В Windows используйте `"command": "cmd", "args": ["/c", "npx", "-y", "github:IgorShutko/horoshop-mcp"]`. Первый запуск скачивает и собирает пакет, это занимает около 20 секунд. У VS Code, Zed, Hermes Agent, Gemini CLI, OpenCode, Goose и других клиентов свой формат настроек: смотрите [инструкцию по установке](docs/INSTALL.ru.md), там же описана установка через клонирование и тайм-ауты клиентов.

**5. Попробуйте.** Попросите агента:

- *«Покажи мои магазины на Хорошопе и проверь, работает ли авторизация.»*
- *«Покажи 10 последних заказов в myshop со статусом и суммой.»*
- *«Каких товаров в myshop нет в наличии? Покажи артикул, название и цену.»*
- *«Задай SEO-заголовок и описание категории /shoes/ на украинском и русском. Только план изменений.»*
- *«Создай 301-редиректы из этого списка старых URL. Сначала покажи план изменений.»*

## Настройка

Сервер берёт все параметры из переменных окружения.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HOROSHOP_STORES_FILE` | нет | Путь к JSON-файлу с магазинами (рекомендуемый способ). |
| `HOROSHOP_STORES` | нет | Тот же JSON прямо в переменной. Имеет приоритет над файлом. |
| `HOROSHOP_DEFAULT_STORE` | единственный магазин, если он один | Магазин для вызовов без `store`. |
| `HOROSHOP_TIMEOUT_MS` | `120000` | Тайм-аут одного HTTP-запроса к магазину. |
| `HOROSHOP_MAX_RESPONSE_BYTES` | `100000` | Ответы инструментов чтения больше этого размера не возвращаются: вместо них сервер подсказывает, как сузить запрос. Также принимается старое название `HOROSHOP_EXPORT_MAX_BYTES`. |
| `HOROSHOP_WIDGET_RETRY` | включено | `off` отключает автоматический повтор идемпотентных записей через виджеты админки (см. [ограничения платформы](#ограничения-платформы)). |
| `HOROSHOP_GRID_REPAIR_MAX` | рассчитывается для каждого списка, не больше 60 | Сколько дополнительных страниц можно перечитать, если длинный список в админке сдвигается во время чтения. |
| `HOROSHOP_IMPORT_POST_LIMIT` | `120000` | Максимум байт в одном запросе `catalog/import`; импорт большего объёма делится автоматически. |

Формат файла с магазинами:

```json
{
  "myshop": { "baseUrl": "https://myshop.com.ua", "login": "api-user", "password": "REPLACE_ME" },
  "othershop": { "baseUrl": "othershop.ua", "login": "api-user", "password": "REPLACE_ME" }
}
```

Ключ задаёт имя, которое потом передают как `store`. `baseUrl` может быть просто доменом, со слешем в конце или с `/api`. Если конфигурации нет, сервер всё равно запускается и показывает инструменты, а вызовы объясняют, чего не хватает. Файл с ошибкой останавливает сервер с понятным сообщением.

## Защита от ошибочных изменений

- **Сначала план.** 57 из 71 инструмента записи по умолчанию работают с `dryRun` и возвращают план: что изменится, с какого значения и на какое. Ничего не записывается, пока вы не повторите вызов с `dryRun:false`.
- **Подтверждение для необратимых и массовых действий.** Удаление или отмена заказов, удаление справочников, смена алиаса фида (это публичный адрес фида) и запуск импорта прайса требуют явного `confirm`. `horoshop_admin_products_price_set` не принимает нулевую или отрицательную цену, для больше чем 50 товаров требует точное число товаров, для изменений больше 50% отдельное подтверждение, и возвращает готовые параметры для отката.
- **Проверка чтением.** Инструменты записи перечитывают результат, часто другим каналом (например, запись через админку проверяется через публичный API), потому что Хорошоп иногда отвечает `OK`, ничего не сохранив.
- **Защита шаблонов.** Тексты витрины часто содержат переменные вроде `{DISCOUNT_PERCENT}` или `{site}`. Инструменты записи не заменят их обычным текстом без `allowPlaceholderLoss:true`.
- **Ограничение размера.** Инструменты чтения измеряют ответ и не возвращают больше 100 KB, а подсказывают, как сузить запрос. Один вызов не засорит разговор.
- **Секреты скрыты.** `horoshop_admin_design_get` не отдаёт раздел оплаты и маскирует значения, похожие на ключи; `horoshop_list_stores` никогда не возвращает доступы.
- **Аннотации инструментов.** Каждый инструмент помечен как чтение, запись или разрушающая запись, поэтому клиенты, которые это поддерживают, могут автоматически разрешать чтение и спрашивать разрешение перед записью.

## Ограничения платформы

Эти ограничения идут от платформы, а не от сервера, и измерены на реальных магазинах:

- **В публичном API есть импорт, но нет удаления.** Товары и покупателей через `/api/` можно создавать и обновлять, но не удалять; категории там доступны только для чтения. Удаление и редактирование категорий закрывают инструменты админки.
- **Экспорт каталога отдаёт не больше 500 товаров за вызов,** независимо от `limit`. Листайте через `offset` и `limit` (100 на страницу работает хорошо).
- **Товары в заказе изменить нельзя** ни через API, ни через админку. Получателя, адрес, оплату и комментарий менеджера изменить можно.
- **Отдельное фото из галереи удалить нельзя.** У Хорошопа нет такого маршрута.
- **Записи через виджеты админки иногда теряются.** Во время всплесков нагрузки часть запросов попадает на витрину вместо админки, и ничего не сохраняется. Идемпотентные записи (обновление, удаление) повторяются до пяти раз, а пропуски попадают в отчёт; создание не повторяется никогда, чтобы не появились дубли.
- **Открытие заказа в админке поднимает его наверх списка заказов** (платформа обновляет дату строки). Данные заказа не меняются; инструменты открывают редактор как можно реже.
- **Дашборд аналитики показывает фиксированный период.** Для произвольных дат собирайте данные через `horoshop_orders_get`.
- **Некоторые разделы существуют, только если в магазине подключён модуль,** например редактор своего CSS. Тогда `horoshop_admin_css_get` возвращает `available:false` вместо пустого результата.

Полный список с подробностями: [docs/INTERNALS.md](docs/INTERNALS.md#platform-notes) (на английском).

## Безопасность

- Храните доступы в файле магазинов или в переменных окружения, никогда не вставляйте их в запросы к агенту или в аргументы инструментов. `stores*.json`, резервные копии и файлы `.env` добавлены в gitignore.
- Создайте для сервера отдельного администратора с самой узкой ролью, которой достаточно для работы. Чтобы закрыть доступ, удалите этого пользователя.
- Сервер обращается только к настроенным магазинам, к сервису загрузки изображений Хорошопа, на который указывает админка во время импорта фото, и к адресам изображений, которые вы сами просите загрузить. Телеметрии нет.
- API-токены и сессии админки хранятся только в памяти.
- Сообщая об ошибке, не вставляйте в issue реальные данные магазина, заказов или доступы.

## Как это работает

Сервер объединяет три канала к магазину:

1. **Публичный API** (`/api/<function>/`): авторизация токеном, который кешируется для каждого магазина и обновляется незаметно. Используется для каталога, заказов, покупателей, справочных данных, B2B и вебхуков.
2. **Админка**: сессия через `/core-api/admin/security/login`, дальше классические экраны админки. Админка устроена единообразно и различает разделы по параметру `handler` (тип сущности): списки, формы редактирования, сохранение. Реестр этих типов даёт небольшому универсальному ядру доступ почти к каждому разделу, а для частых задач есть отдельные инструменты. Запись читает всю форму, меняет только нужные поля и отправляет остальное без изменений, поэтому поля, которых вы не касались, сохраняются.
3. **Витрина**: собственный виджет корзины магазина (`/_widget/ajax_cart/`) для вопросов, на которые API не отвечает. Например, сможет ли покупатель дойти до оформления заказа с определённым способом доставки.

## Частые вопросы

### Что такое Хорошоп MCP?

Хорошоп MCP реализует протокол Model Context Protocol для интернет-магазинов на Хорошопе. Подключённый к нему ИИ-агент читает и меняет магазин через 118 инструментов: товары, заказы, покупателей, категории, SEO-тексты, 301-редиректы, фиды маркетплейсов, дизайн и настройки. Сервер с открытым исходным кодом работает локально и может обслуживать несколько магазинов одновременно.

### Является ли Хорошоп MCP официальным продуктом Хорошопа?

Нет. Хорошоп MCP разрабатывается независимо и не связан с компанией Хорошоп. Сервер использует публичный API Хорошопа, а всё, чего в API нет, делает теми же запросами, которые отправляет интерфейс админки. Эти внутренние запросы могут измениться в любой момент, поэтому новые сценарии проверяйте на отдельном тестовом магазине.

### Какие ИИ-ассистенты работают с Хорошоп MCP?

Любой MCP-клиент, который умеет запускать локальный stdio-сервер. В [инструкции по установке](docs/INSTALL.ru.md) есть пошаговая настройка для 22 клиентов, среди них Claude Code, Claude Desktop, Cursor, OpenAI Codex, Hermes Agent, VS Code с GitHub Copilot, Windsurf, Gemini CLI, Zed и Cline.

### Что нужно, чтобы подключить магазин на Хорошопе?

Node.js 18 или новее, Git, а также логин и пароль администратора вашего магазина на Хорошопе. Запишите доступы в `stores.json`, добавьте сервер в ИИ-клиент одной командой и подождите около 20 секунд, пока первый запуск соберёт пакет.

### Безопасно ли давать ИИ-агенту доступ к магазину?

Сервер спроектирован именно для этого. 57 из 71 инструмента записи только показывают план, пока вы не передадите `dryRun:false`, необратимые действия требуют явного `confirm`, а каждая запись проверяется чтением результата. Доступы хранятся в локальном файле, телеметрии нет. Дайте серверу отдельного администратора с самой узкой ролью, которой достаточно.

### Можно ли управлять несколькими магазинами с одного сервера?

Да. Опишите все магазины в одном файле `stores.json`, а каждый вызов выбирает магазин аргументом `store`. Так агентство работает с магазинами всех клиентов через одно подключение.

### Сколько стоит Хорошоп MCP?

Хорошоп MCP бесплатный и распространяется по лицензии MIT. Платите только за свой тариф Хорошопа и за ИИ-клиент, которым пользуетесь.

## Разработка

```bash
git clone https://github.com/IgorShutko/horoshop-mcp.git
cd horoshop-mcp
npm install          # installs dependencies and builds dist/
npm run watch        # recompile on change
npm run inspect      # build and open the MCP Inspector
npm run docs:tools   # regenerate docs/TOOLS.md from the running server
```

MCP-клиенты запускают сервер один раз, поэтому после пересборки перезапустите клиент. `horoshop_check_auth` и `horoshop_list_stores` возвращают `stale:true`, если сборка на диске новее запущенного процесса.

В `evaluation/horoshop_eval.xml` собраны вопросы только на чтение, чтобы проверить, справляется ли модель с реальными задачами через сервер. Ответы зависят от подключённого магазина, поэтому заполняйте их на своём тестовом магазине.
