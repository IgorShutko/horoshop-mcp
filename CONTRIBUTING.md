# Як допомогти проєкту

Дякую за інтерес. Найкорисніше зараз: повідомлення про інструменти, які повертають не те, що показує адмінка, і розділи адмінки, яких ще немає серед 118 інструментів.

## Збірка і перевірка

```bash
npm install
npm run build          # tsc
npm test               # піднімає сервер, перевіряє список інструментів і чистоту stdout
npm run docs:tools     # перегенерувати довідник інструментів
npm run inspect        # MCP Inspector на зібраному сервері
```

Перед пулл-реквестом мають проходити `npm run build`, `npm test` і `npm run docs:tools:check`. У CI ганяються ті самі команди на Node 18 і 22.

## Правила, які легко порушити

- **Інструментів не меншає.** `npm test` падає, якщо їх стало менше 118. Прибирати інструмент - окреме рішення, не побічний ефект рефакторингу.
- **stdout - це канал JSON-RPC.** Будь-який `console.log` ламає всіх клієнтів. Логи йдуть у `console.error`.
- **Запис за замовчуванням сухий.** Новий інструмент запису приймає `dryRun` і без `dryRun:false` тільки показує план. Ризиковані масові операції додатково вимагають явного підтвердження.
- **Перевіряти результат другим читанням.** Платформа вміє відповідати `success` там, де запису не сталося. Після запису інструмент перечитує те, що записав.
- **Довідник не редагується руками.** `docs/TOOLS.md`, `docs/tools/*.md` і `docs/tools.json` генеруються з відповіді сервера `tools/list`. Змінили інструмент - виконайте `npm run docs:tools` і закоміть результат.
- **Ніяких доступів у діфі.** `stores.json` у `.gitignore`. Перед комітом перевіряйте, що в коді, тестах і документації немає логінів, паролів, токенів і адрес клієнтських адмінок.
- **Тире.** У текстах і описах інструментів використовуємо звичайний дефіс, не довге тире.

## Як додати інструмент

1. Опишіть його у відповідному файлі `src/tools/` як `ToolSpec`: `name` (починається з `horoshop_`), `title`, `description`, `inputSchema` (з `...storeField`), `annotations` і `handler`.
2. Додайте набір до `src/index.ts`, якщо створили новий файл.
3. `npm run build && npm test && npm run docs:tools`.
4. У пулл-реквесті скажіть, на якому магазині перевіряли. Тестовий - так, чужий робочий - ні.

## Структура

```
src/index.ts        точка входу, збирає набори інструментів
src/config.ts       stores.json, нормалізація адреси магазину
src/client.ts       публічний API Хорошопу
src/admin/          рушій адмінки: сесія, розбір форм, гарди, маскування секретів
src/tools/          самі інструменти, по розділах
scripts/smoke.mjs   димовий тест
scripts/tools-doc.mjs  генератор довідника
docs/               документація: встановлення, довідник, внутрішній устрій
```
